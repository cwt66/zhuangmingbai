# 可复算演示（Demo as Code）

> 2026-11-11 新增。起因很直接：校赛要交 3 分钟演示视频，
> 但手录一次 90 分钟、每次改版都要重录、评委也无法验证
> 「你视频里演示的」和「你仓库里跑的」是不是同一个东西。

---

## 一、它是什么

把演示的 8 个镜头写成剧本（`scripts/auto_demo.py`），一条命令：

```bash
python3 scripts/auto_demo.py --run --spawn     # 起临时服务、跑 8 镜、截图 + 时间轴
python3 scripts/auto_demo.py --verify --spawn  # 重跑，与基线比对结构
python3 scripts/auto_demo.py --self-test       # 静态双向断言（不开浏览器）
```

产出：

| 产物 | 内容 | 是否入库 |
|---|---|---|
| `out/demo/s01…s08.png` | 8 张 1920×1080 关键帧 | 否（`out/` 已忽略） |
| `out/demo_timeline.json` | 每镜状态、命中关键词、截图 sha256、耗时 | 否 |
| `data/demo_timeline_v0.json` | 基线（只含可复算字段） | **是** |
| `out/demo/demo.webm` | 可选录屏（`--record`） | 否 |

## 二、对标（borrowed，不宣称原创）

| 项目 | 它做了什么 | 我们借了什么 | **没做到** |
|---|---|---|---|
| `charmbracelet/vhs` | 把终端演示写成 `.tape`，渲染成 GIF/MP4/WebM | 「演示是源码，可 review、可重跑」 | 我们驱动的是浏览器不是终端；没有它的帧率/主题语言 |
| `AlexKay28/clickcast` | Playwright 录制 + JSON sidecar + **distilled assertions**（只比 step/状态/错误计数，不比时间戳、URL、像素） | distilled 的字段取舍：删掉墙钟、耗时、截图哈希 | 我们没做像素级 diff，也没有 GIF/MP4 自动编码 |
| Playwright | `screenshot` / `record_video` / 自动等待 | 全部截图与录屏能力 | 没有 trace viewer 集成 |

**一句话差异**：同类工具解决「怎么录」，我们多走一步——
**录出来的东西可以被下一个人用一条命令复算**，且复算只比结构不比像素。

## 三、8 镜与证据

| 镜 | 名称 | 画面来源 | 硬断言（页面正文必须出现） |
|---|---|---|---|
| s01 | 封面 / 上传入口 | `/` | 装明白 · 可计算审计 / 上传报价单 |
| s02 | 样例结构与字段 | `/`（滚到样例表并高亮） | 样例 A / 样例 B / 漏 17 项 |
| s03 | 三家表面报价 | `/demo` | 3 家报价 / 86,498 / 59,902 |
| s04 | B 的 17 项漏项 | `/demo` | 漏项 / 基准 |
| s05 | 真实成本反转 | `/demo` | 真实成本 |
| s06 | 证据三档与审计编号 | `/demo` | 证据 |
| s07 | 照片识别与校对 | `/perceive` | 识别 / 校对 |
| s08 | 架构与云底座 | `docs/assets/deck-architecture.png` | （图片页，无文本断言） |

`--verify` 比对的是 **distilled shape**：

```json
{"steps": [{"id":"s01","path":"/","status":"ok","hits":["上传报价单","装明白 · 可计算审计"]}]}
```

不含：墙钟时间、单镜耗时、截图 sha256、截图字节数、base_url。
理由与 clickcast 一致——这些字段每次运行都会变，留着会让复算永远 FAIL。

## 四、边界（和证据一起读）

- **不比对像素**：字体、抗锯齿、Chromium 版本不同，同一页截图必然有差异。
  截图 sha256 只作为「本次运行」的证据写在 `out/` 里，不入库、不参与复算。
- **需要浏览器**：`--run` / `--verify` 依赖 Playwright + Chromium。
  服务器默认没有（`command -v chromium` 为空），所以这是**本机制作动作**，
  不是 CI 步骤；CI 只跑 `--self-test`（纯静态，8 项断言）。
- **不是视频编码器**：`--record` 出的是 webm，转 mp4 需要 ffmpeg；
  脚本不做转码，避免把编码参数写死。
- **断言是「词在页面上」**：能抓住「页面白了 / 报错页 / 字段丢了」，
  抓不住「数字算错了」——算错由 `eval/` 的判据管。

## 五、和 3 分钟视频的关系

8 张关键帧就是**分镜底稿**：`国奖提交包/03_演示视频/3分钟演示脚本_v4.md`
里的 8 个镜头与 s01–s08 一一对应。录制时：

1. 先跑 `--run`，确认 8 镜全绿（页面没坏、字段没丢）；
2. 按 `视频提词器_3分钟.md` 的逐字稿配音；
3. 想要动态画面再加 `--record` 出 webm，或直接手录。

改代码后重跑一次，分镜自动更新——**不用再「重录一遍」**。
