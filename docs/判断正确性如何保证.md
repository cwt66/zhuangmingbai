# 给你一张装修报价单，凭什么说我的判断是对的

> 这份文档回答一个问题：**输入是一张陌生的报价单，输出是一堆「你漏了 / 你重了 / 你对不上账」的结论——这些结论凭什么可信？**
> 它不是宣传材料，是把「正确性」拆到可以被别人攻击、并且能被别人复算的程度。

---

## 0. 先把问题问准

「判断正确」这句话其实混了四件事，必须分开：

| 问题 | 能不能证明 | 我们怎么处理 |
|---|---|---|
| ① 这条结论**在文字上**站得住吗？ | **能**，可逐条回原文 | 每条结论带行号 + 基准 + 公式 |
| ② 同一份输入，**别人算出来一样吗**？ | **能**，可离线复算 | 审计包 + 判定摘要 digest |
| ③ 这个判断**符合行业事实**吗？ | **部分能**，取决于基准 | 模板/本体/规则三份标准全部可审阅 |
| ④ 该报的**都报了吗**（召回）？ | **不能完全证明** | 只能给可扩展的下界 + 明确说清边界 |

**我们不宣称 ④ 已被证明。** 谁宣称了，谁就在骗人——真实世界没有「全知标注」。

---

## 1. 第一道闸：只判可判定的命题

装修报价里绝大多数争议是主观的：这家贵不贵、活儿好不好、值不值。**这三件事我们一律不判**，写进报告口径。

我们只判四种**能被算术和文本证据裁决**的命题：

| 判定 | 命题形式 | 为什么可判定 |
|---|---|---|
| 漏项 | 「模板要求的第 K 项，在这份单据里没有任何文字证据」 | 可穷举检索：概念对齐 + 别名 + 证据词 + 否定语境 |
| 重复计价 | 「同一概念在同一分区被计费两次」 | 可数：分组键（概念+分区）+ 变体判别 |
| 算术 | 「数量×单价 ≠ 合价」 | 可算 |
| 文档对账 | 「工序明细之和 + 取费 ≠ 印刷合计」 | 可算 |
| 口径 | 「原文出现『按实结算 / 暂定 / 另计』等开口词」 | 可检索（不推断动机） |

**这条边界是可信度的前提**：如果什么都判，就一条都不可信。判得少、判得准，比判得多、判得虚要值钱。

---

## 2. 第二道闸：每条结论都必须带「可复算的证据结构」

引擎输出的每一条结论都长这样（不是形容词，是字段）：

```
{ 概念: 门窗保护, 规则: R1, 档位: auto, 置信度: 0.94,
  基准: 标准工序模板（老房翻新）39 项,
  公式: T \ S（模板必做项 − 实列项），再扣除文本证据命中项,
  检索词: [门窗保护, 成品保护, 保护膜],
  参照: 参照价库（n 份中位）,
  行号: —（漏项无行号，因为是「没有」）}
```

**任何人可以拿这份输出回到原表，逐条核对：**
- 说「门窗保护漏了」→ 你去全文搜这四个字和它的 3 个别名，搜不到就是漏了；
- 说「第 38、57 行重复」→ 你去看这两行的项目名与分区，是不是同一件事收了两次；
- 说「整单差 11,711」→ 你把明细加一遍，再加取费，和印刷合计比。

**结论不是「AI 觉得」，是「一个可被复算的命题」。**

---

## 3. 第三道闸：真值从四个互不相同的来源来

单靠一个来源都有盲区，所以我们交叉了四路：

| 来源 | 它证明什么 | 它不能证明什么 |
|---|---|---|
| **文档内锚点**（印刷小计/合计/实收） | 这份单据**自己**对不对得上账 | 单据本身造假时无效 |
| **跨单参照**（同批其他报价） | 漏项补上大概要多少钱 | 只有一份时无参照 |
| **人工黄金标注**（先标注、后跑引擎、冻结） | 真实脏数据上的判定对不对 | 单一标注者；样本小 |
| **程序注入**（242 个已知缺陷） | 规则对已知缺陷形态的检出能力 | 不代表真实召回率 |

### 3.1 为什么「先标注、后跑」是硬规矩

黄金标注必须在**看引擎输出之前**冻结（`eval/golden_labels_*.csv` 里记着标注者与时间）。
否则标注会被引擎输出污染——本项目真发生过一次：第一遍标注 P=R=1.0，
原因就是标注时看了引擎结果。那次结果**没有写进任何材料**，只作为反面教材留在缺陷册里。

### 3.2 为什么还要「注入实验」

人工标注只有 2 份、且是单一标注者。注入实验换一条路：真值由程序埋，规模不受人力限制。
**但它的 100% 不是召回率**——埋的缺陷形态由我定义，天然偏向引擎能识别的形态。
它的真实用途是：**每次改代码重跑一遍，任何一条规则退化立刻掉分**（回归哨兵）。

## 4. 第四道闸：审计包——把「可复现」变成别人能动手做的事

**口头说可复现是没有成本的，所以不可信。** 我们的做法是打一个包：

```
feitai_audit.zmb.zip (45 KB)
├── input.csv          被审单据（逐字节冻结）
├── standards/         当时的模板/本体/规则/覆盖率/参照价库/范围标签
├── src/               当时的判定引擎（零第三方依赖）
├── result.json        结论 + 输入哈希 + 标准哈希 + 结论摘要 digest
├── verify.py          离线校验器
└── README.txt
```

第三方解压后跑 `python3 verify.py`：

- 输入被改一个数字 → **FAIL**（sha256 不匹配）
- 标准被换成别的版本 → 不可能，标准在包里
- 复算结论与记录不一致 → **FAIL**（digest 不匹配）

实测：

```
[PASS] 复算结论与包内记录一致：52bf7b635204fd96
```

把 input.csv 里一个 280 改成 281 之后：

```
[FAIL] 输入文件已被改动
  记录 44c8286479fbebf8…
  实际 1754220505528fd9…
```

**这就是「判断正确」最硬的形态**：不是让你信我，是让你 30 秒内自己验一遍。

## 5. 明确说清：我们证明不了什么

| 做不到 | 为什么 | 我们怎么标注 |
|---|---|---|
| 完整的召回率 | 没有「全知标注」，真实世界不存在完备真值 | 只报有黄金标注的 2 份单据统计（翡翠台 8/8、124㎡ 范围内 4/4），并注明单一标注者 |
| 「模板 100% 完备」 | 模板是人定的 39/28 项，本身可争议 | 模板逐项可审阅；错模板的代价有实测（花溪：对模板 4 条，错模板 16 条） |
| 「转录 100% 完整」 | 照片会遮挡，人工转录会漏行 | 每份单据做算术自校验；翡翠台对账差 11,711 元里，明确写了「**可能是我转录缺行**」 |
| 「原单一定造假」 | 差额也可能来自取费未单列 | 对账条列出三个可能来源，让用户去问，而不是直接指控 |

**这几行是这份文档最重要的部分。** 一个系统能说清自己不能证明什么，它说的「能证明」才可信。

## 6. 一个完整走查：从一张陌生单据到一条结论

以翡翠台（123 行 + 8 行汇总）为例：

1. **分层**：8 行汇总（造价/管理费/设计费/总造价/主材小计/合计/实收）被认出来并移出工序明细。
   判据是算术门控（缺单价 / 数量×单价≠合价 / 费率行），不是关键词硬匹配——
   诊所 PDF 里 19 行「批腻子…小计」是真工序（数量×单价=合价精确），一刀切会误删。
2. **对齐**：123 行里 102 行对到本体概念（82.9%），其余 21 行明确标为「未对齐」，
   **不假装对齐**——未对齐行不参与概念级判定。
3. **判漏**：模板 39 项逐项检索，命中概念或证据词即算存在；否定语境（"不含/另计"）不算证据。
   结果：确定漏项 8 条 + 建议复核 2 条。
4. **对账**：明细 153,384 + 取费 11,748 = 165,132，印刷合计 176,843，**差 11,711 → 不符**。
5. **计价体系**：识别为「工程量清单（量价齐全）」，置信度 0.78 → 提示「漏项与重复结论可直接采信」。
6. **开口条款**：扫出「另计」等表述，产出「签约前必须书面确认」清单。
7. **出报告**：每条结论带行号/基准/公式/档位；报告编号 + 判定摘要 digest 上封面。
8. **打包**：`make_bundle.py` 出 45KB 审计包，任何人 `verify.py` 复算。

第 8 步是关键：**前面 7 步的任何一步被质疑，都能退回第 8 步当场验。**

## 7. 为什么不让大模型直接判

这是架构选择，不是技术能力不足：

| | 大模型直接判 | 本系统 |
|---|---|---|
| 同一输入两次输出 | 可能不同 | 摘要恒同（digest 可验） |
| 结论定位 | 「大概在瓷砖部分」 | 行号 38、57 |
| 出错时 | 无法定位错在哪一步 | 分层→对齐→判漏→对账，可分段验证 |
| 被质疑时 | 只能重跑一次碰运气 | 出审计包，对方自己复算 |

**大模型负责「看懂」（OCR/VLM 解析），规则负责「裁决」**——把不确定的部分和确定的部分分开，
才能分别定位错误。这也是我们在感知层保留四种 provider、并把解析与判定彻底解耦的原因。

---

## 8. 一页总结

> **我的判断不是「AI 认为」，而是一组可复算的命题：**
> ① 只判可判定的（漏/重/算术/对账/口径），不判贵不贵、好不好、值不值；
> ② 每条结论带行号、基准、公式、置信度、档位，能回到原文逐条核对；
> ③ 真值来自四路互不相同的来源（单据自证、跨单参照、人工标注、程序注入）；
> ④ 任何人可以拿审计包 30 秒离线复算，改一个数字立刻 FAIL；
> ⑤ 说不清的地方明确标注为「待确认」或「无法证明」，不进金额。

如果这五条里有任何一条被推翻，结论就不成立——**这正是它可信的原因**。
