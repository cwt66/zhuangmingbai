# 技术架构：为什么「判断」必须离开大模型

> 这份文档回答评委最常问的三个问题：
> 1. 大模型在这里到底干什么？
> 2. 换一家公司/换一个行业，为什么还能用？
> 3. 出错的时候，用户知不知道？

## 2. 为什么不让大模型直接下结论

| 问题 | LLM 直读 | 规则裁决（本项目） |
|---|---|---|
| 同一单跑两次 | 可能两份报告 | 同一份（冻结指纹可验） |
| 结论溯源 | "AI 认为" | 行号 + 基准 + 公式 |
| 跨单对齐 | 靠上下文记忆 | 本体库显式归一 |
| 错的时候 | 用户不知道 | 三档处置，低分不进钱 |
| 回归测试 | 无法写 | 99 个单测 + 242 例注入 + 评测门禁 |
| 换行业 | 重写提示词 | 换三份 JSON，引擎零改动 |

**大模型是必需品，但不是裁决者**：没有它，照片/手写/合并单元格进不来，报告也写不成人话；
有了它，如果让它裁决，就失去了可复核性。所以我们把它的职责压缩到「理解」与「表达」两端。

## 3. 云原生映射

| 层 | 华为云服务 | 代码 | 失败行为 |
|---|---|---|---|
| 开发全过程 | CodeArts 码道 | 五环节留痕（需求/生成/构建/修复/部署） | — |
| 感知（照片） | ModelArts Studio Qwen-VL | `src/perception.py::_maas_parse` | 显式报错，提示开通 |
| 感知（表格） | 文字识别 OCR 通用表格 | `src/perception.py::_ocr_table_parse` | 显式报错，提示订阅 |
| 判断 | 本地纯标准库 | `src/pipeline.py` | 不依赖网络 |
| 持久化 | RDS for PostgreSQL | `src/store.py` | 降级 SQLite，`/health` 标注 |
| 缓存/限流/任务 | DCS for Redis | `src/cache.py` | 降级进程内，`/health` 标注 |
| 表达 | ModelArts Studio 文本模型 | `src/llm.py` | 接地失败/超时 → 模板，页面标注 |
| 原件/报告 | OBS | 预签名 URL（部署手册） | 本地临时文件 |
| 公网入口 | ECS + Nginx + HTTPS | `deploy/` | 本地 uvicorn 可演示 |

**一个原则**：云服务失败时，产品可以降级，但**不能假装成功**。
`/health` 会逐项返回 `kind`、`degraded`、`configured`，评委可以当场核对。

## 3.6 本地 OCR + critic（v0.5 新增）

云端 MaaS 需要 Key 与额度；真实用户第一步却是"拍一张报价单"。所以新增：

- `provider=vision`：macOS Vision 在本机做中文/英文 OCR，图片不出机器；
- 表格重建：按表头「单位 / 工程量 / 单价 / 小计」推断列，按数量/单价锚点聚行；
- **critic**：缺项目名/单位/数量/单价/合价、数量×单价≠合价（2% 容差）、置信度 <0.3
  → 标为「需核对」；
- **质量门**：需核对比例 >35% 时，`/perceive` 不直接出审计报告，而是进入
  「识别草稿：先校对，再审计」页面；用户改完 CSV 再 POST `/vision/audit`。

这不是"识别得更准"，而是**承认识别会错，并把错误挡在结论之前**。
`/health` 会返回 `vision.available`，评委可当场核对本机是否具备该能力。

## 3.7 评测门禁（v0.5 新增）

`eval/gate.py` 把"可复算"变成 CI 硬约束：auto 精确率/召回率 <0.75、all 召回 <0.90、
注入检出 <230、消融 L2 精确率 <0.75 → 退出码 1。`scripts/check_all.sh` 每次都会跑。
门禁不是为了刷分，是为了防止「改一条规则把数字改坏」还合并。

## 3.8 报告质量门（v0.5）

每份审计报告顶部有一行「质量门」：

- 对齐：`aligned / rows`（对齐率 <60% 标「需复核」）
- 算术：可校验行数 + 不符行数（任一行不符 → 需复核）
- 漏项 / 重复 / 风险条数
- 对账：印刷合计与差额（若有）
- 分位对账：用 `Decimal` 再算一遍「明细 + 取费 vs 印刷合计」，差到分；R8 的 1 元容差不变，
  但读者能看到「在容差内」不等于「精确对平」
- 判定指纹

`/report/{id}` 历史页同步展示同一组指标；`payload.quality` 落库。
它不是"评分"，是**让读者先知道这份报告的证据强度**，再决定看哪一节。

## 4. 数据流与幂等

```
上传 → 临时文件 → 解析 → 行项 JSON → 对齐 → 审计 → 摘要落库 → 报告
                                      │
                                      └── 判定指纹 sha256（同一输入同一指纹）
```

- 审计编号 `A-xxxxxxxx` 写入 RDS；`/report/{id}` 可回看摘要。
- 判定指纹写进报告封面；改一个数字，指纹变化，回归测试失败。
- 审计包把输入、规则版本、判定结果、校验器打成一个 zip；`verify.py` 离线复算。

## 5. 失败模式清单（设计时就写下来）

| 失败 | 表现 | 处理 |
|---|---|---|
| 照片斜拍/阴影 | OCR 产出伪表格 | 明确报错 + 提示重拍；不拿烂结果继续 |
| PDF 无文本层 | 解析为空 | 抛「没有文本层」，不返回空表 |
| 表头缺失 | 列全空 | 表头别名 + 结构兜底；仍失败则明确报错 |
| GBK/TSV | 乱码/空列 | 编码嗅探 + 分隔符嗅探 |
| 汇总行 | 总价翻倍 | 算术门控分层，不按关键词一刀切 |
| 模板选错 | 漏项全错 | 模板/范围显式参数，写进报告 |
| 数据库挂 | 报告打不开 | 降级 SQLite；`/health` 标注 |
| Redis 挂 | 限流失效 | 降级进程内；`/health` 标注 |
| 模型编数字 | 解读不可信 | 接地校验拒收 → 模板兜底 |
| 单据注入指令 | 模型被带跑 | 定界符隔离 + 注入识别 + 接地校验 |

## 6. 可迁移性：判定能力在数据里

`src/pipeline.py` 不包含任何装修专有名词。领域知识全部在：

- `data/ontology_v0.json`（概念/别名/单位/上下位）
- `data/templates_v0.json`（工序模板）
- `data/coverage_v0.json`（证据词/父类吸收）
- `data/rules_v0.json`（规则阈值与判据）

汽修迁移实验只换了 `data/repair/` 下三份 JSON，引擎文件零改动，跑出：
对齐 19/19、漏项 4、重复 1、算术 1、对账差 30 元、开口条款 2 类。
迁移过程中抓出两处隐式领域耦合（`onto["u"]`、`_cross_unit`），已修并锁进 7 个测试。

**「可迁移」不是形容词，是 7 个测试用例。**
