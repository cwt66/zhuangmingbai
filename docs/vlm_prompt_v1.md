# VLM 解析提示词 v1 + 输出 Schema

> 用途：把手机拍的报价单（照片/PDF 转图）解析成引擎可读的结构化行项。
> 原则：**只做"看"和"抄"，不做"判断"**——判断在 `src/pipeline.py` 里，由规则完成。
> 对应赛题："需求理解 → 代码生成 → 项目构建 → 问题修复 → 部署上线"中的感知层。

---

## 1. 系统提示词（直接粘进 MaaS / CodeArts）

```
你是一名装修报价单结构化解析器。你的唯一任务是把图片中的报价表格"照抄"成 JSON，
不做任何判断、不做金额修正、不做项目合并、不补全图片中没有的内容。

【输出格式】严格输出 JSON，不要输出 markdown 代码块、不要解释：
{
  "doc": {"city": null, "area": null, "scene": null, "company": null, "page": 1},
  "rows": [
    {
      "no": "1",
      "name": "拆墙",
      "spec": "非承重墙",
      "unit": "㎡",
      "qty": 8,
      "price": 55,
      "amount": 440,
      "note": "",
      "confidence": {"name": 0.98, "spec": 0.9, "unit": 0.99, "qty": 0.97, "price": 0.96, "amount": 0.99}
    }
  ],
  "page_notes": ["第2页表格跨页，已按行合并"]
}

【字段规则】
1. 合并单元格：按行展开——同一项目覆盖多行时，每一行都要写出该项目名。
2. 数量/单价/合价：只抄图片上的数字；若图片只给合价、无单价，price 置 null、amount 照抄。
3. 单位：只能取 项/㎡/m/樘/块/根/个/位/套；图片写"平方/平米/平"→㎡，"米/延米"→m，"只/扇"→樘或个（按语境）。
4. 名称：照抄原文，不做同义词替换（"墙固"就写"墙固"，不要改成"界面剂"）。
5. 备注：图片中的"按实结算/暂定/另计/不含/单边/按根"等字样必须抄进 note，不得省略。
6. 看不清：字段置 null，confidence 置 0.3 以下，并在 page_notes 写明"第X行第Y列模糊"。
7. 不准编造：图片没有的行、没有的数字、没有的品牌型号，一律不写。
8. 手写涂改：以最终可见数字为准；若两种笔迹冲突，取清晰者并在 page_notes 标注。

【置信度约定】
- 0.95–1.00：印刷清晰、表格对齐
- 0.80–0.94：轻微模糊/倾斜/合并单元格推断
- 0.60–0.79：需人工确认（手写、涂改、遮挡）
- <0.60：基本不可读，字段置 null

只输出 JSON。
```

**用户提示词**（每张图一条）：
```
请解析这张报价单图片。这是第 1/3 页。房型：老房翻新；城市：杭州；套内面积：约 80㎡（若图片中有则以此为准）。
```

## 2. 输出 JSON Schema

见 `data/schema_parse.json`（可直接用于结构化输出校验；校验失败重试一次，仍失败则降级为人工录入）。

关键约束：
- `rows` 至少 1 行
- `qty`/`price`/`amount` 为 number 或 null
- `confidence` 六个字段均为 0–1
- `unit` 枚举

---

## 3. 与引擎的接口

```
图片/PDF
  → VLM（本提示词）
  → JSON（Schema 校验）
  → 转 CSV（data/samples 的 8 列格式；无值留空）
  → src/pipeline.py（本体对齐 + 三类审计 + 证据链 + 报告）
```

**转 CSV 规则**：
- `qty`/`price`/`amount` 为 null → 留空（引擎按 0 处理并触发 R9 规则）
- `confidence` 不写入 CSV，单独存 `out/parse_conf.json`（供校对页标黄与置信度合成）

## 4. 提示词评测（W2 做）

| 指标 | 定义 | 目标 |
|---|---|---|
| 字段准确率 | 六个字段逐字段与人工转录一致的比例 | ≥85%（20 份单据） |
| 行召回 | 图片中存在的行被解析出的比例 | ≥95% |
| 金额一致率 | `qty×price` 与 `amount` 一致（容差 1 元）的比例 | ≥98% |
| 低置信度命中率 | 人工判定"需确认"的单元格中，模型给 <0.8 的比例 | ≥70% |

> 评测脚本：`eval/eval_parse.py`（待建，W2 与真实单据同步）。
