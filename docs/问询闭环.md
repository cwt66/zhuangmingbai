# 问询闭环：新版报价到底改了几条

## 一、为什么需要这一步

问询单解决的是「我该问什么」。但真实流程还有下半场：对方回一份「已修改」的新版，
业主只会看总价——总价降了 3,000 元，看起来有诚意。

问题在于这三件事可以同时发生：

- 问的漏项补上了（+1,200）
- 另一项单价悄悄上调（+2,600）
- 顺手又加了一项「变更补报」（+200）

总价确实降了，但**问的问题只解决了一部分**，还多了一个新问题。

所以本轮把「问询单」当成施工里的 **punch list（整改清单）**：
每条问询是一个待关闭项，新版报价是对方的「整改回执」，逐条判 **已落实 / 未落实**，
并把**新版新增的问题单独列出来**。

## 二、判定规则（每条都能指回原表）

| 问询类型 | 判「已落实」的条件 | 依据写到哪 |
|---|---|---|
| 漏项（可估价 / 工艺项） | 新版出现同一概念且金额 > 0 | 新版行号 + 金额 |
| 重复计价 | 新版**引擎不再判该项为重复**（不用「数行数」：同一概念合法拆成多行时数行会误判） | 新版仍被判重复的行号 |
| 算术不符 | 新版该行不再出现在 `R8_arithmetic` 里 | 行号 + 剩余差额 |
| 整单对账 | 新版明细合计与印刷合计已对齐（容差按 `R13` 的 `tolerance_pct`） | 差额 |
| 计量口径 | 新版该项的量纲集合 ≤ 1（`m` 与 `M` 视为同一量纲） | 统一后的量纲 + 行号 |
| 开口条款 | 新版原文不再出现该条款的关键词 | 消失的关键词 |

判不了的一律标 `unknown`，**不猜**。比如旧版问询单没有 `kind` 锚点时，
闭环不会硬套一个结论上去。

## 三、为什么必须单列「新增问题」

这是从 `reviewdog` 的 `-filter-mode=added` 学来的：只报**本次改动新引入**的问题，
否则存量问题会把新增的埋掉。

放到这里就是：补了闭水试验（已落实 +1），同时新增「成品保护」漏项（+1）——
只报「落实率 100%」等于替对方背书。

实现上比较的是**两版审计结果的差异键**（漏项 cid / 重复 cid / 风险 `(rule, line)`），
不是金额：金额变了不算新问题，否则一涨价就刷屏。

## 四、边界（写在输出里，不藏在文档）

- **只核对事实变化，不评价答复**：写「闭水试验已单列（第 132 行）」，不写「对方有诚意」；
  写「单价由 18 调到 22」，不写「涨价不合理」。
- **不判断「答复是否充分」**：对方补了一行「闭水试验 150 元」，是否够、做法对不对，
  不在判定范围内。
- **落实率不是评分**：它只是「问的 N 条里改了几条」，分母不含无法核对的条目。
- **同义改写会判「未落实」**：判定按概念 id 对齐，对方把「门窗保护」写成「成品保护（门窗）」时
  对不上——这是**宁可漏判**的取舍：与其替对方宣布「已补」，不如让人再看一眼。
  每条的「依据」里写了它在找哪个概念，人工核对时能直接对。同样的道理，
  分组风险（如「另计」多行）只按规则判「新出现」，不因行号集合变化而报新问题。

## 五、实测：一份「已修改」的新版到底改了几条

用仓库里的真实单据（翡翠台，153,384 元）和它的变更版跑一遍：

```
问询 19 条 ｜ 已落实 1 ｜ 未落实 18 ｜ 无法核对 0 ｜ 落实率 5%
总价 153,384.00 → 154,048.00（+664.00）
```

| 结果 | 内容 |
|---|---|
| 唯一落实 | 闭水试验（新版第 132 行，150 元） |
| 最典型的未落实 | 12 条漏项里 11 条一字未动 |
| 同义改写漏判 | 新版补了「成品保护（门窗）」，问的是「门窗保护」，概念 id 对不上 → 判未落实（宁可漏判） |
| 新增问题 | 0（新版没有引入新的漏项 / 重复 / 口径问题） |

**要注意**：这份 `feitai_change_demo.csv` 本来是用来演示「改价」的（乳胶漆 18→22、
垃圾清运 95→105㎡、删一行重复），不是一份针对问询单的整改回执。所以 5% 是**如实结果**，
不是判定失灵——如果换成真实回执，这个数才有对比意义。

真正值得注意的是：**总价涨了 664 元，但 19 条里只解决了 1 条**。
只看总价，业主会以为「对方改了」；跑一遍才知道改的是哪一条。

## 六、复算

```bash
# 真实单据 → 变更版（仓库内演示数据）
python3 scripts/check_followup.py \
  --before data/real/feitai_budget.csv \
  --after  data/samples/feitai_change_demo.csv \
  --out out

# 判据自测（双向断言）
python3 src/followup.py --self-test
```

产出 `out/followup_<after>.md` 与同名 `.json`。

网页版：`python3 -m uvicorn main:app --port 8000` 后打开 `/followup`。
页面上半部是**上传入口**：第 1 份传原版、第 2 份传对方回的新版（CSV / XLSX，各 ≤ 4MB，
过文档守门与表头校验），模板可选「老房翻新 / 新房毛坯」——选错模板漏项结论全错，
所以做成显式选择而不是猜。下半部默认是仓库内的演示结果，上传后会替换成你的两版。

> 边界：只核**同一项目、同一计价口径**的两版，不做跨公司比价。
> 拿 A 公司和 B 公司的报价来核，得到的「落实率」没有意义。

同一份结果有两个渲染器，所以自测里锁了「HTML 行数 = 条目数 + 1」、
「上传表单只出现一次且在明细表之前」，并检查**报价单里的项目名被转义**——
一张单据就能注入脚本，这个口子不能留。
