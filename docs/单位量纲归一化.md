# 单位量纲归一化（R5 降噪）

> 2026-11-11。起因是一次真实单据扫描：5 份真实报价单里，
> `㎡ / m2 / 平方米 / M / m / 只 / 套 / 樘` 大量混用，
> 而跨单单位比较（R5）当时是**按字符串比**的。

---

## 一、问题

`cross_unit_mix()` 原来的判据是：

```python
units[cid][label].add(r["unit"])      # 直接收原始字符串
if len(allu) > 1: ...                 # 有两种写法就报
```

后果：**等价写法被当成风险**。

| 概念 | 各单写法 | 实际含义 | 旧判据 |
|---|---|---|---|
| 贴地砖 | `m2` / `㎡` | 完全等价 | ❌ 报「单位不一致」 |
| 踢脚线 | `M` / `m` | 完全等价（大小写） | ❌ 报 |
| 木门安装 | `只` / `套` / `樘` | 都是个数 | ❌ 报 |
| 拆墙 | `m` / `m2` / `㎡` | 米 vs 平方米，**量纲不同** | ✅ 该报 |
| 柜体定制 | `M` / `m` / `m2` / `付` / `套` | 延米 vs 面积 vs 数量 | ✅ 该报 |

旧判据把两类混在一起：**写法差异**和**量纲差异**。

---

## 二、修法

加一层量纲映射（`src/pipeline.py`）：

```python
UNIT_DIM = {
    "㎡": "area", "m2": "area", "平方米": "area", "平米": "area",
    "m": "length", "米": "length", "延米": "length",
    "项": "item", "宗": "item",
    "个": "count", "只": "count", "樘": "count", "套": "count",
    "m3": "volume", "车": "trip", ...
}
```

R5 改成比**量纲集合**：

- 量纲集合 ≤ 1（如 `{area}`）→ 不报（`m2/㎡` 是同一件事）
- 量纲集合 ≥ 2（如 `{area, length}`）→ 报「量纲不可比」
- `项` 单列：它是计价方式（包干），不是量纲；由 R6 单独管
- **认不出的单位一律不判**——宁可漏报，不把看不懂的写法当风险

---

## 三、实测效果（5 份真实单据）

| | 条数 | 说明 |
|---|---:|---|
| 改前 | **27** | 含 `m2/㎡`、`M/m`、`只/套/樘` 等 17 条等价写法 |
| 改后 | **10** | 全部是量纲真的不同 |

改后保留的 10 条：

| 概念 | 量纲组合 | 为什么该报 |
|---|---|---|
| 布线 | length / count | 按米 vs 按根 vs 按端口，不可直接比价 |
| 门槛石 | length / count | 按米 vs 按块 |
| 铝扣板吊顶 | area / count | 按面积 vs 按根 |
| 包立管 | area / count | 按面积 vs 按根 |
| 窗台石 | area / length | 按面积 vs 按米 |
| 灯具安装 | length / count | 灯带按米、筒灯按个，概念粒度过粗 |
| 拆墙 | area / length | 墙面积 vs 墙长 |
| 砌墙 | area / count | 面积 vs 块 |
| 垃圾清运 | area / trip | 面积 vs 车 |
| 柜体定制 | area / length / count | 面积 vs 延米 vs 数量 |

**这些都不是「错」，而是「不可直接比价」**——R5 的语义本来就是这个，
low severity、review 档、不进核减金额，只提示人工。

R5 不进钱，所以金额类指标不动——这也是一次「降噪不降能力」的验证。

## 五、为什么不顺手把 A3 也修了

红队 A3 是「㎡ 写成 m」，单份单据内。看起来加一条「面积工序按长度报价即异常」就能拦住，但实测会误伤：

| 单据 | 行 | 工序 | 单位 | 本体 | 判断 |
|---|---|---|---:|---|---|
| feitai | 113、114 | 柜体定制 | m | ㎡ | **合法**：橱柜按延米报价 |
| szxinxin | 1–8 | 柜体定制 | M | ㎡ | **合法**：同上 |
| feitai_ocr | 1–24 | 拆墙/铲墙皮/贴砖… | m / m' | ㎡ | OCR 把 ㎡ 认成 m，是识别问题 |

柜体按延米是行业惯例，本体默认单位写 `㎡` 本身就不够细。
要判它需要「概念 → 可接受量纲集合」的知识表（`cabinet: {length, area}`），
而不是一条全局规则。**本轮不做**，并把这个判断写进了负向知识库 NA13
（`data/not_applicable_v0.json`），另有测试锁住「不许为了让 A3 变绿而加粗暴规则」。

> 这也是本项目的一条纪律：**发现边界时，先写清边界，再决定要不要修**。
> 为了让红队数字好看而加一条会误伤的规则，是把「7/8」换成「8/8 但到处误报」，
> 净亏。
