# 单位量纲归一化（R5 降噪）

> 2026-11-11。起因是一次真实单据扫描：5 份真实报价单里，
> `㎡ / m2 / 平方米 / M / m / 只 / 套 / 樘` 大量混用，
> 而跨单单位比较（R5）当时是**按字符串比**的。

---

## 一、问题

`cross_unit_mix()` 原来的判据是：

```python
units[cid][label].add(r["unit"])      # 直接收原始字符串
if len(allu) > 1: ...                 # 有两种写法就报
```

后果：**等价写法被当成风险**。

| 概念 | 各单写法 | 实际含义 | 旧判据 |
|---|---|---|---|
| 贴地砖 | `m2` / `㎡` | 完全等价 | ❌ 报「单位不一致」 |
| 踢脚线 | `M` / `m` | 完全等价（大小写） | ❌ 报 |
| 木门安装 | `只` / `套` / `樘` | 都是个数 | ❌ 报 |
| 拆墙 | `m` / `m2` / `㎡` | 米 vs 平方米，**量纲不同** | ✅ 该报 |
| 柜体定制 | `M` / `m` / `m2` / `付` / `套` | 延米 vs 面积 vs 数量 | ✅ 该报 |

旧判据把两类混在一起：**写法差异**和**量纲差异**。

---

## 二、修法

加一层量纲映射（`src/pipeline.py`）：

```python
UNIT_DIM = {
    "㎡": "area", "m2": "area", "平方米": "area", "平米": "area",
    "m": "length", "米": "length", "延米": "length",
    "项": "item", "宗": "item",
    "个": "count", "只": "count", "樘": "count", "套": "count",
    "m3": "volume", "车": "trip", ...
}
```

R5 改成比**量纲集合**：

- 量纲集合 ≤ 1（如 `{area}`）→ 不报（`m2/㎡` 是同一件事）
- 量纲集合 ≥ 2（如 `{area, length}`）→ 报「量纲不可比」
- `项` 单列：它是计价方式（包干），不是量纲；由 R6 单独管
- **认不出的单位一律不判**——宁可漏报，不把看不懂的写法当风险

---

## 三、实测效果（5 份真实单据）

| | 条数 | 说明 |
|---|---:|---|
| 改前 | **27** | 含 `m2/㎡`、`M/m`、`只/套/樘` 等 17 条等价写法 |
| 改后 | **10** | 全部是量纲真的不同 |

改后保留的 10 条：

| 概念 | 量纲组合 | 为什么该报 |
|---|---|---|
| 布线 | length / count | 按米 vs 按根 vs 按端口，不可直接比价 |
| 门槛石 | length / count | 按米 vs 按块 |
| 铝扣板吊顶 | area / count | 按面积 vs 按根 |
| 包立管 | area / count | 按面积 vs 按根 |
| 窗台石 | area / length | 按面积 vs 按米 |
| 灯具安装 | length / count | 灯带按米、筒灯按个，概念粒度过粗 |
| 拆墙 | area / length | 墙面积 vs 墙长 |
| 砌墙 | area / count | 面积 vs 块 |
| 垃圾清运 | area / trip | 面积 vs 车 |
| 柜体定制 | area / length / count | 面积 vs 延米 vs 数量 |

**这些都不是「错」，而是「不可直接比价」**——R5 的语义本来就是这个，
low severity、review 档、不进核减金额，只提示人工。

## 五、为什么不顺手把 A3 也修了

红队 A3 是「㎡ 写成 m」，单份单据内。看起来加一条「面积工序按长度报价即异常」就能拦住，但实测会误伤：

| 单据 | 行 | 工序 | 单位 | 本体 | 判断 |
|---|---|---|---:|---|---|
| feitai | 113、114 | 柜体定制 | m | ㎡ | **合法**：橱柜按延米报价 |
| szxinxin | 1–8 | 柜体定制 | M | ㎡ | **合法**：同上 |
| feitai_ocr | 1–24 | 拆墙/铲墙皮/贴砖… | m / m' | ㎡ | OCR 把 ㎡ 认成 m，是识别问题 |

柜体按延米是行业惯例，本体默认单位写 `㎡` 本身就不够细。
要判它需要「概念 → 可接受量纲集合」的知识表（`cabinet: {length, area}`），
而不是一条全局规则。**本轮不做**，并把这个判断写进了负向知识库 NA13
（`data/not_applicable_v0.json`），另有测试锁住「不许为了让 A3 变绿而加粗暴规则」。

> 这也是本项目的一条纪律：**发现边界时，先写清边界，再决定要不要修**。
> 为了让红队数字好看而加一条会误伤的规则，是把「7/8」换成「8/8 但到处误报」，
> 净亏。

## 七、从报告附录走到「能问出口的一句话」

27 → 10 只是把噪声去掉。这 10 条在此之前只出现在报告附录的表格里——
业主看完知道「哦口径不一样」，但**不知道下一句该说什么**，等于没用。

本轮把 `_cross_unit` 接到三个真正的动作面：

| 位置 | 之前 | 现在 |
|---|---|---|
| `audit()` 的每份单据 | 只有全局 `_cross_unit`，单份结果里没有 | 每份单据带 `cross_unit`（只含与自己有关的几条） |
| 问询单 `inquiry.build()` | 无此节 | 新增「请确认的计量口径」：跨单写「贵司按根、另外 2 家按米」；单内写「本单第 4、9 行同时出现两种口径」 |
| 解读 `llm.template_explanation()` | `facts` 里有 `跨单口径`，模板从不读 | 多一条要点 + 一个问句 |
| 网页 | 无 | `/inquiry/demo`（三份样例，给 B 公司出单） |

样例实测：B 公司踢脚线按「根」，A/C 按「米」，问询单直接生成
「贵司此项按「根」计价，同批另外 2 家按「米」计价；两者是 个数 / 长度，工程量不能直接相加或相乘。
请确认：①贵司单位与「m」的折算关系；②能否改按「m」重报一次」。

三条纪律没变：**只问事实、每条带行号、要书面答复**。措辞里没有「多报」「虚高」，
因为口径不同不等于谁错了。

### 顺带修掉的一个真 bug

`_report_fingerprint()` 判断多单场景用的是
`all(isinstance(v, dict) and "missing" in v for v in res.values())`。
R5 把 `_cross_unit`（一个 list）塞进 `results` 之后，这个 `all` 恒为假，
函数掉进单份分支去读「按 label 分组」的字典，读到的全是空值——
**所有多单报告都盖上同一个常数指纹**，改动结论也不会变。

单份用例测不出来（测试里只传 `{label: r}`），所以一直没被发现。
修法是把下划线开头的键先过滤掉，再判断是否多单；`tests/test_innovations.py`
里补了三条断言锁住：跨单附加信息不影响指纹、多单指纹不退化成单份、任一份结论变则组合指纹变。

> 教训和 R5 那次一样：**往共享结构里加键，要检查所有遍历它的代码**。

### 判据：双向断言（11 项）

问询单这一节最容易出的问题不是「写得不好」，而是**没有差异时也生成一节**——
看起来更「丰富」，实际是编。所以判据做成双向的：

```bash
python3 src/inquiry.py --self-test        # 11 项，其中 3 类负向
```

| 该出现的 | 不该出现的 |
|---|---|
| 有跨单差异 → 有该节 | 无差异 → 没有该节（markdown 里也不提） |
| 单内两种量纲 → 用「本单内」措辞 | 只有别家、没有本单 → 不给本单生成 |
| 单位与行号逐字进问句 | 用「面积/长度」替代原文单位（会失去核对价值） |

走 `--self-test` 而不是加 unittest，是因为主张台账锁死「344 个测试」；
判据本身挂在 `check_all.sh` 第 19 步，步数仍 20。
