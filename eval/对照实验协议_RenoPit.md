# RenoPit 对照实验协议（预注册版）

> 版本 v1.0（协议冻结于 2026-10-31，先于任何对照实验数据产出）
> 对标《国奖打底方案》6.3 节：「这是唯一能反驳『别人做过了』的东西」。
> **预注册声明**：本协议在跑任何对照实验之前冻结。指标定义、评分表、盲评流程全部先行确定；
> 实验后只报数字，不改口径。若结果不利，如实报告——协议本身就是为了防"调参到好看"。

## 1. 要回答的问题

答辩必问："RenoPit 这类开源项目已经做了 AI 装修审查，你们有什么区别？"

**标准答案不能靠说，要靠数字。** 本实验让两类系统在同一批单据上各跑一遍，用同一把尺子量：

| | RenoPit（装闭） | 装明白 |
|---|---|---|
| 技术路线 | 多模态 LLM 直读文档 → 批判性分析报告 | 本体归一到工序轴 → 规则引擎裁决 → 证据链报告 |
| 结论来源 | 大模型生成 | 12 条规则 + 模板集合差 + 算术校验 |
| 开源地址 | github.com/fthux/RenoPit（2026-06 活跃） | 本仓库 |
| 预期差异 | 读得懂，但结论无法指到行号、跑两次不一样 | 每条结论带 行号+基准+公式+置信度，指纹可复现 |

**命题（可证伪）**：在可溯源率与可复现性上，规则裁决路线显著优于 LLM 直读路线；
在漏项召回上两者可比（我们不预设自己赢，输了如实报）。

## 2. 对照对象确认（2026-10-31 核实）

- 仓库真实存在，最近 commit 2026-06/07（README 更新 07-17，deepwiki badge 10-21），非弃坑项目
- 技术栈：OpenAI 兼容 API 的多模态 LLM；Docker Compose 一键部署；前端 3000 / 后端 8000
- 功能：上传设计图 + 合同/报价单（TXT/MD/DOCX/PDF）→ 批判性分析 → 在线报告 + PDF
- **本机无 Docker**（缺陷登记册 #12），故：
  - **主路线**：官方在线 Demo `renopit.fthux.com` 人工提交同一批单据文本，收集其报告
  - **备用路线**：ECS 上 Docker 部署（若在线 Demo 限额或不可用）

## 4. 指标定义（先于实验冻结）

### M1 漏项召回（对照黄金标注）
`召回 = 双方报出的真漏项 ∩ 黄金标注 / 黄金标注漏项总数`
- 黄金标注 = 模板 39/28 项 × 每份单据的 presence（present / missing / not-applicable），双人独立标注 ≥80% 一致，分歧第三人仲裁
- 现状：标注表已建（`eval/golden_labels_TEMPLATE.csv`），**缺第二标注人**——这是召回率一栏始终空着的唯一原因

### M2 结论可溯源率（主指标）
`可溯源率 = 能同时给出(原表行号 + 对照基准 + 计算公式)的结论数 / 结论总数`
- 装明白：引擎结构化输出，直接统计
- RenoPit：人工逐条判定其报告中的每个"问题"是否给出可核对的行号与基准；给出即算可溯源
- 判定规则写死：**行号指不到原文具体行 = 不可溯源；"报价偏低"这类无基准陈述 = 不可溯源**

### M3 可复现性（同输入跑 3 次）
- 装明白：3 次 `snapshot_predictions.py` 指纹比对（预期 3 次全同）
- RenoPit：同单提交 3 次（间隔 ≥1h），输出文本逐条 diff，报告"结论条数变化 / 金额变化 / 新增删除条目"
- 量化：`一致性 = 3 次输出中逐字相同的结论条数 / 平均结论条数`

### M4 幻觉条目数
`幻觉 = 报出的"问题"中，回原文核实不成立的条数`
- 双方同规则：报出的每条问题在原文中找不到依据即计幻觉（与 M2 独立：一条结论可以"可溯源"但"溯源后不成立"）

## 5. 流程（五步，全程留痕）

1. **准备**（0.5 天）：CSV→带行号纯文本 ×6；黄金标注表补齐（需第二标注人）；两系统账号/环境就绪
2. **跑批**（0.5 天）：RenoPit 每份单据提交 3 次（M3），存档全部原始输出截图/文本，文件名 `renopit_run{1,2,3}_doc{n}.md`；装明白同批跑 3 次出指纹
3. **盲评**（0.5 天）：两系统全部结论去掉系统名与格式 → 统一编号打乱 → 按第 6 节评分表逐条判（行号可否指认 / 基准有无 / 回原文是否成立）
4. **统计**（0.5 天）：M1-M4 汇总成一张对照表（模板见第 7 节）
5. **报告**（0.5 天）：结果写入 `eval/对照实验结果.md`，无论输赢；答辩 PPT 加一页

**留痕要求**：RenoPit 的每次提交与完整响应存档（截图 + 文本），防止"你说它不行"的空口质疑。

## 6. 盲评评分表（每条结论一行）

| 字段 | 取值 | 说明 |
|---|---|---|
| item_id | 系统-单据-序号 | 打乱后重新编号 |
| conclusion | 结论原文 | 原样粘贴 |
| has_line | yes/no/部分 | 能否指到原表行号 |
| has_basis | yes/no | 有无对照基准（模板项/国标/规则名） |
| has_formula | yes/no | 有无可复算的公式或金额推导 |
| traceable | auto 计算 | 三项全 yes = 可溯源 |
| grounded | yes/no | 回原文核实是否成立 |
| note | 自由文本 | 争议备注 |

## 8. 局限（预先声明）

1. RenoPit 在线 Demo 的模型版本/提示词不受我们控制，结论仅代表"该类路线的公开实现"，不代表 LLM 直读路线的上界。
2. 单据数量受黄金标注人力限制（n=6），结论是方向性的，不是统计显著的。
3. 盲评仍由项目成员执行（无第三方），主观误差存在；评分表与原始留痕全公开以补救。
